## 修复行为

| 建议 | 实现与边界 |
| --- | --- |
| MT-UX-004 | `npm run dev` 使用跨平台 Node 启动器，为子进程设置显式 development 浏览器模式，默认监听 loopback。非 development 配置拒绝启动；代理额外检查 `NODE_ENV=production`，继续校验 Host、Origin、Fetch Metadata 和 CSRF。启动读取保留 HTTP 状态；403 显示配置提示并停止自动重试，临时网络/5xx 错误仍可自动恢复。 |
| MT-UX-001 | `accept` 的 Promise 覆盖父会话读取、状态同步、WS 接受与 child 会话读取，完成/失败/取消才结束。同步 ref 防止重复进入，每次操作独立持有 AbortController、socket、timer；旧回调不能结束新操作，卸载会中止读取并清理连接。公共错误帧立即结束，状态同步失败与失效邀请分别提示；接受后跳转失败引导刷新列表后继续练习。 |
| MT-UX-002 | 实施第一阶段离开保护：文字/图片草稿、资料范围草案和知识库笔记使用统一确认；侧栏切换、新建、题库等链接和刷新/关闭受保护。取消后保留文字、选择位置和附件，确认丢弃或发送成功才清理。作答草稿记录题目 cycle/revision，题目变化后禁止直接提交，并提供改为提问或丢弃。没有新增跨会话自动恢复，也没有将学生文本/截图写入浏览器持久存储。 |
| MT-UX-005 | `DesktopApiError` 保留 status/code。仅原生 picker 明确返回 501 才打开浏览器选择器，422/500 不自动重选。导入返回后立即显示文档，归属 PATCH 失败保留结果并提供只重试归属的操作；列表刷新失败不会改称导入失败。PATCH 响应丢失时标注范围尚待确认，刷新发现已全局共享则解除恢复提示。 |
| MT-UX-006 | 通知与文档行共享状态文案：分别表达 ready、解析警告、needs_ocr、failed、检索停用与未归类。只有 ready/ready_with_warnings、存在分块且 retrieval_enabled 才可说可检索；未归类明确说明需要关联或设置共享范围。通知可定位并聚焦文档行的现有重新解析/删除控件。 |

浏览器脚本复现（在已启动的开发前端旁执行，故障脚本不使用真实业务数据）：

```bash
cd web
LAYOUT_URL=http://127.0.0.1:3000 \
PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs \
CHROME_EXECUTABLE=/absolute/path/to/chrome \
node scripts/smoke-ux-lifecycle.mjs
```

`PLAYWRIGHT_MODULE` 可省略以使用已安装的 `playwright`；`CHROME_EXECUTABLE` 可省略以使用其浏览器。本次复用了本机现有测试工具，没有新增 npm 依赖。
