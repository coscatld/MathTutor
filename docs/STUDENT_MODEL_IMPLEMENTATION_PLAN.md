# MathTutor 学习画像、推荐练习与共享学生模型实施方案

编制日期：2026-09-13。依据：本次提供的改进建议，以及当前工作区代码与验收文档的静态核对。

实施顺序：**先交付基于学习证据的画像与推荐闭环，再完成迁移模型实验，最后按验收结果分发模型资源包。** 第一阶段即可形成可发布的产品增量。模型实验、数据准备和教学效果验证分别记录进度。

本文件记录整体实施契约。PR 1–4 的首批实现与实测结果见 `docs/STUDENT_PROFILE_DELIVERY.md`；数据核查见 `docs/STUDENT_DATA_AVAILABILITY.md`。P3–P5 的迁移、校准和资源包指标仍是待实施规划。

## 1. 目标、范围与关键决定

最终闭环：可靠作答证据 → 可追溯的学习画像 → 有理由的下一步练习 → 新的独立作答证据。

| 决策项 | 本轮采用的方案 |
| --- | --- |
| 学生模型 | 沿用 LSTM/DKT，共享参数，每个本地档案隔离个人 h/c |
| 默认策略 | 继续由 EvidenceTracker 提供证据依据；DKT 先影子运行 |
| 冷启动 | 零历史使用通用基线；有少量有效证据后实验软匹配轨迹先验 |
| 产品页面 | “我的数据”拆成“学习画像”和“设置 → 数据与隐私”；“练习邀请”改为“推荐练习” |
| 推荐流程 | 复用现有 offer 接受流程、父子练习导航与教学状态机 |
| 部署 | 开发环境 PyTorch 训练，产品环境 NumPy 推理；通过验收的公共模型随包分发 |
| 数据 | 学习事件为事实源，摘要、隐状态与推荐依据为派生产物；用户偏好单独保存 |
| 后续范围 | 联邦学习、个人梯度微调、元学习、ONNX 迁移进入后续候选清单 |

本地档案标识继续复用当前 owner/student scope。模型工作不引入联网账户，也不改变 Embedding 的独立开关。云端讲解沿用其独立配置与数据使用说明。

总工程量约 24–39 人日。前后端两人协作时，P1/P2 与 P3 可分工推进，P5 可先用实验包验证工程链路。不要把人日简单除以人数作为承诺工期，联调和实验存在串行依赖。

两个发布里程碑：**M1 = P1 + P2，以 EvidenceTracker 发布页面闭环；M2 = P3 + P4 + P5，通过门禁后分发稳定模型。** 模型未达标时，M1 仍可发布，模型包维持实验状态。

## 4. P0：冻结事件与读写契约

### 4.1 统一事实、估计与偏好

学习事件保留现有不可变结构和服务端写入边界。补齐或明确 `label_policy_version`、判定来源、映射版本、题目版本、预测时历史截点。新增字段需要事件版本兼容策略与数据库迁移；旧记录缺失字段显式记为未知。

主预测任务定义为：在题目呈现时，使用此前可见历史预测该题首次独立整题作答正确的概率。

实现时将该主预测绑定到题目开始/呈现事件，保存不可变历史截点与题目信息；作答提交时只关联结果。当前按 attempt 准备的预测记录可作为过程分析保留，但不能混作呈现时预测。补测“呈现 → 请求提示 → 提交”的顺序，确认提示后的信息没有进入呈现时主预测。

“首次”以本地档案与规范化题目版本为边界，在序列处理时判定。首次有效独立整题作答之后，同题再答保留为学习历史，退出该题主损失；重复提交、换会话、换 cycle 均不能重置首次资格。若更早已有无法判定或来源不明的作答，保留资格不确定标记并退出主目标，避免把后续成功当成首次成功。

受助、答案后作答、步骤完成与自述按已有语义记录。跳过、未作答和未知判定不产生错误标签。诊断事件可进入可见历史；当前诊断不进入主损失的规则继续保留，诊断结果单列评估。

首次标签按事件时间顺序冻结，后续教学不能倒改已经成立的独立事实。以下为强制回归契约：

| 实际顺序 | 首次独立整题标签 |
| --- | --- |
| 呈现 → 首次独立答对 | 1 |
| 呈现 → 首次独立答错 → 提示 → 最终答对 | 保留 0 |
| 呈现 → 先得到提示 → 答对 | 空，退出主目标 |
| 呈现 → 首次无法核验 → 再答对 | 空，首次资格不确定 |
| 首次作答被排除 → 同题再次答对 → 重启重放 | 后一次仍非首次成功 |

当前代码会在整批事件上调用 `valid_events`。离线评估需要明确两种视图：用于当前画像重算的“最终纠正视图”，以及用于模拟历史决策的“截至当时已知视图”。未来的失效事件不能提前改变过去的输入。最终复核结果可作为评估标签，但需记录标签版本和可用时间。

### 4.2 拟定接口增量

路径均相对于现有对应 router 前缀。沿用 `StudentOwnerScope`，档案身份由服务端上下文确定。

| 接口 | 作用与主要字段 |
| --- | --- |
| 扩展 `GET /student-summary` | `schema_version`、`coverage`、`last_event_seq`；每技能给出分结果计数、联合证据、最近检查、证据状态与下一步入口 |
| 新增 `GET /student-evidence?skill_id=…&cursor=…` | 分页返回公开事件引用、题目摘要、作答/步骤、核验结论、帮助状态、时间和会话定位 |
| 新增 `POST /student-evidence/{event_id}/exclude` | 幂等排除当前档案的一条作答证据，追加失效事件并触发重算，返回新投影版本 |
| 新增 `POST /privacy/recompute-profile` | 从当前有效事件重算派生状态；保留原始事件和历史预测日志 |
| 扩展 `GET /offers` | 推荐意图、理由、依据事件、题量、观察目标、子周期、更新原因、完成摘要 |
| 新增 `POST /offers/{offer_id}/feedback` | `later` 或 `not_relevant`；独立于作答标签，包含幂等键 |

证据详情采用字段白名单。显示用户自己的作答和经核验的公开解释，不通过画像或推荐接口提前暴露尚未展示的标准答案、验证器日志或内部提示词。原会话不可用时，详情显示可用的证据摘要和“原会话不可打开”。

兼容期保留旧响应字段与 `mastery=null`，新前端读取带版本的结构化计数。空画像统一返回“尚未检查”，联合题证据与诊断分别列示。

## 5. P1：学习画像与推荐练习

### 5.1 学习画像

拟新增 `LearningProfilePanel.tsx` 与 `SkillEvidenceDrawer.tsx`，在 `DesktopShell.tsx` 增加可直接打开的画像入口。原 `PrivacyPanel.tsx` 的维护内容拆为设置内的 `DataPrivacySettings.tsx`，相关请求函数复用 `desktop-api.ts`。

页面按以下顺序组织：

1. 当前学习目标与最近学习摘要。目标来自用户设置，观察摘要来自事件投影。
2. 技能卡片默认突出一个有依据的观察、一句证据说明和一个下一步动作；“查看依据”展开分结果计数、题目、帮助状态与时间。
3. 尚未检查的技能，明确本版本覆盖范围；全部为空时提供开始当前题目或可跳过诊断入口。
4. 点击技能展开证据详情，提供“这条记录有问题”入口和相关练习入口。

结论文案使用确定性模板与结构化字段，例如“有 2 道新题独立完成，仍缺不同题型的检查”。模板中的“新题”“独立完成”“不同题型”必须分别有题目去重、事件语义和题族支持。联合题证据不能拆成多个技能的独立成功次数。

第一版采用卡片/列表与详情抽屉，完整知识图谱作为后续视图。空数据、加载失败、请求重试、键盘操作、焦点恢复和窄窗口布局纳入页面验收。

另设“已有问答但尚缺可核验的独立作答”空态：问答或图片讨论不自动形成能力证据，页面解释完成一道可核验的新题后将新增观察。问答存在性仅用于空态选择，不计入能力统计。

### 5.2 推荐练习

保留 `/math-tutor/offers` 路由，统一导航、标题、空态和加载文案。`PracticeOfferCard.tsx` 已有“开始练习”按钮，可直接复用。

每条推荐公开以下内容：练习目标、推荐理由、依据事件引用、实际题量、完成后观察目标。优先从已有 `PracticeRecommendation.purpose` 和 `decision_reason` 构造结构化说明；缺少依据时显示用户主动练习等真实来源。

页面只突出一个主推荐，另列最多两个备选。排序先采用可解释的确定性规则：当前目标相关性、有效证据缺口、推荐新鲜度与用户反馈。排序版本随记录保存。没有合格候选时显示空态与主动练习入口。

存在进行中或可恢复练习时，页面主操作优先为“继续练习”；只有没有进行中练习时才突出新推荐。完成摘要增加“查看学习记录”，直接定位本次新增证据。

目前 offer 关联单个练习。第一版按实际资源显示“1 道题”，不将候选数量当作题量；两题练习包需要后续显式的练习组结构。

| 页面区域 | 判定依据 | 用户操作 |
| --- | --- | --- |
| 待开始 | 有效且尚未接受的推荐 | 开始、稍后、这不是我想练的 |
| 进行中 | 已接受，关联子周期尚未完成，包括可恢复的暂停状态 | 继续练习 |
| 已完成 | 关联子周期达到服务端完成条件，并有本次结果 | 查看本次观察 |
| 需要更新/历史 | 过期、撤回、拒绝、失败或已关闭未完成，分别显示原因 | 查看原因；有资格时重新评估 |

接受状态与完成状态分别从推荐记录和教学周期获得。重复点击继续复用现有幂等接受及父子导航逻辑。已接受题目固定在子周期中，新推荐不得替换它。

推荐绑定生成时的 `history_cutoff_seq`、目标版本和策略版本。作答或证据更正后，由服务端判断待开始推荐是否需要更新；仅页面刷新不创建新推荐。说明需要更新的真实原因，不展示催促倒计时。

“稍后”作为推荐反馈保存并抑制反复出现，“不相关”进入偏好反馈；两者均不写入能力标签。练习结束后，只汇总对应子周期的有效新证据：独立完成、仍有帮助的步骤与后续检查点。汇总中区分未作答、退出与完成。

## 6. P2：纠错、重算与删除

第一版纠错提供“排除这条记录”，后续再接自动重新核验。受信服务验证记录归属，只允许通过此入口排除作答证据；帮助暴露事实不由用户随意撤销，以免旧题被重新认定为独立作答。更正判定时，应保留原始作答身份与时间绑定。

排除只撤销该记录参与能力判断和训练标签的资格，保留“该题曾经作答”的时间占位。重放、导出与训练视图均使用该占位判定首次资格；不得将后一次成功提升为首次成功。删除全部学习数据则同时删除这些占位，不另存隐蔽个人学习历史。

复用 `StudentStateService.invalidate()` 的失效事件机制，统一重算以下消费者：学习画像、教学证据、当前 h/c、尚未开始的推荐。审计日志保留当时的历史预测，新增派生版本标识其依据已变化。

新增显式画像重算服务，取代外部调用私有 `_checkpoint()`。重算绑定事件上界与模型版本；有新增事件时补增量或重试。模型更换一律从有效事件重放，不复用旧参数的 h/c。

删除与重算采用档案级串行协调，覆盖该档案所有会话。删除开始时阻止新评估写入，并让在途旧代次写入失效；事务提交后恢复新作答。可以采用持久化 `learning_generation`，在写入提交时校验代次，防止并发请求重建已删除状态。

“设置 → 数据与隐私”分别提供资料管理、记忆管理、学习记录管理、导出、重建检索索引、重新计算学习画像。删除学习记录时，清除事实、预测、快照及新增个人派生缓存；依赖被删证据的待开始推荐撤回或去除旧依据。

确认文案：

> 将删除学习证据及其生成的画像和个性化状态。会话内容保留，但不会自动用于恢复已删除的学习画像。备份中的旧记录需要单独管理。

保留现有聊天清理与来源未知规则。重启、旧数据导入、索引重建均不能从保留聊天自动恢复已删证据。显式恢复旧备份可以恢复其中记录，恢复前应清楚提示这一结果。

## 7. P3：训练数据与冷启动评估底座

### 7.1 数据进入方式

拟在 `knowledge_tracing/adapters/` 添加外部数据适配器，将来源数据转换为统一学习事件。ASSISTments 可作为首个待核查候选，入库前确认具体版本的字段说明、使用条件和模型再分发条件，保存来源与许可记录。未知的帮助先后顺序保留未知，不由总提示次数伪造动作序列。

数据产物包括：

| 产物 | 内容 |
| --- | --- |
| 来源清单 | 数据版本、校验值、取得方式、允许用途、许可与模型分发条件 |
| 技能映射表 | 来源技能定义、目标技能、映射依据、部分覆盖、未知项及审核状态 |
| 标签审计 | 独立目标、受助、答案后、未知、首次资格、失效和重复事件的数量 |
| 划分清单 | 学生、题目、近重复题组与题族归属；清除数量和最终保留规模 |
| 冻结数据快照 | 事件、映射版本、标签策略、数据哈希及可重复生成配置 |

目标域数据使用明确允许训练的结构化事件。保持本地档案隔离，研究数据中的来源标识与学生键组合后再去标识化，防止不同数据集同号学生混合。原始聊天不进入默认训练导出；训练文件和个人派生产物保存在仓库外。

### 7.2 迁移前的特征兼容

当前输入层维度依赖技能、题族和错误类型词表，外部权重不能直接按数组位置装入目标模型。第一版优先选择能映射到当前技能的来源子集预训练。

目标适配时按词表键显式搬运事件投影层与预测层对应列，复用维度兼容的 LSTM 参数，新技能/题族列重新初始化，未知项走现有 OOV 掩码。新增迁移清单记录每个参数的复用或初始化来源，并检查所有维度和语义。

归一化、难度标定、词表、原型只在相应训练数据上拟合。模型选择、先验强度和校准使用目标验证集；测试集保持封存。全部 13 个技能不能映射时，模型支持范围按实际覆盖列示，范围外走证据回退。

### 7.3 冷启动协议

主实验明确为“未见学生＋已有课程范围”，不同学生回答同一课程题目允许跨划分共享，报告共享题比例。禁止跨分区的重复是同一次作答的复制记录、多技能展开行和重复导入；先按来源、学生、原始作答身份合并，不把跨学生同题当作复制记录。另设“未见学生＋未见题目/题族”压力测试，同时留出学生和题目组，报告清除后的有效规模。当前无条件跨划分同题清除逻辑须由显式协议替代；单独题族划分不能命名为同时留出学生。

精确报告 0、1、3、5、10 次有效交互后的预测。当前 `sequence_length` 以全部历史事件数计数，需要新增 `eligible_observation_count`，按经过核验、非重复的新题作答计数，帮助生命周期事件不增加检查点计数。诊断与普通练习的计数分别记录；辅助报告已获得的独立主目标数量。

检查点固定在下一道新题呈现前，输入仅含该时刻已有历史和题目信息。仅在首次整题作答之前已受助、或首次无法核验时将主标签置空；首次独立答错后才得到提示仍保留 0。报告标签保留率、排除原因和帮助信息缺失率。独立指标仅适用于合法独立标签样本，不能推断被排除的求助学生在无帮助时的表现，也不能将求助记成错误。检查点 0 要求无先前学习事件，区分已有教学但没有有效作答的情形。

A/B/C/D 在同一批测试学生、同一题、同一历史截点比较。未达到检查点的学生记为未覆盖；各组不得自行删除预测困难样本。超出模型范围的题目同时报告条件性能和含回退的端到端性能。

## 8. P4：迁移与相似轨迹先验

| 组别 | 配置 | 对照目的 |
| --- | --- | --- |
| A | EvidenceTracker 与同一可见历史 | 现有证据基线 |
| B | 仅目标训练集训练 DKT | DKT 对基线的增量 |
| C | 外部预训练、目标域适配 DKT | 参数迁移的增量 |
| D | C 加聚合轨迹先验 | 相似轨迹先验的增量 |

复用当前三种 seed 17/29/43 作为首批实验配置，训练数据划分和模型初始化种子分别记录。每组使用一致的目标样本与可比较的调参预算。选型和校准可拆分验证集或交叉拟合，测试集不参与选择。

A 的概率规则冻结为 `evidence_beta_v1`：对题目所涉及的每个技能，以截点 H 中有效的单技能独立整题成功/失败计数 C、W，计算 `(C+1)/(C+W+2)`，再按题目技能去重后的等权平均得到 `p_A(q|H)`。未知技能或无历史技能为 0.5；空技能集为 0.5。多技能联合成功不复制为多个技能成功，已可靠定位的错误按现有证据规则归属。版本一不额外校准，先验 Beta(1,1) 为固定配置，输出仅供内部评估，页面仍保持 `mastery=null`。为避免弱基线偏置，可在验证阶段比较候选 Beta 先验与温度校准；所有拟合仅用训练/验证集，最终 A 的公式、参数、校准方式与数据哈希在测试前冻结，不能根据测试结果变更。

### 8.1 原型构建与推理

拟新增 `prototypes.py`、`transfer.py`、`cold_start.py`。原型来自训练学生历史前缀，特征包括技能覆盖、独立作答结果、帮助使用、题族和可比较的难度信息。每个原型需由多个学生贡献，限制单个长序列的权重；包中仅保存聚合统计，不带成员身份与个人隐状态。

对前缀聚类时使用前缀可见特征。原型的下一题结果先验，可在训练集内利用这些前缀之后的合法目标拟合；用于确定相似性的输入始终停在前缀截点。原型数、匹配温度、最低群体支持和收缩强度在验证阶段确定。

预测按以下实验形式融合：

`p_final = (1 - lambda) * p_dkt + lambda * sum(weight_j * prior_j)`

`weight_j` 为归一化软匹配权重，`prior_j` 按技能和可比较难度统计并向通用基线收缩。难度不可比较时使用缺失掩码，并降低匹配贡献或禁用该维度。

零证据、课程不兼容、原型支持不足或匹配质量不够时 `lambda=0`。少量证据时启用有限贡献，随后随个人证据增多衰减。可将 `lambda <= 0.3` 作为首批候选范围，最终值只由验证集确定；并单独校准融合后的概率。此上限是实验设置。

### 8.2 评估与发布门禁

主要指标为学生等权的 Log loss，Brier 为共同检查指标；补充 AUROC/AUPRC、ECE、校准曲线、技能分组和覆盖率。对单标签或样本不足的分组报告不可计算状态。

在相同学生上计算模型与对照的损失差值，以学生为单位配对重采样，给出差值的 95% 区间。复用当前 bootstrap 框架并增加配对差值逻辑，避免仅比较两组各自的区间。

建议在 P3 结束时冻结以下门禁候选，取得测试结果后不修改：

| 门禁 | 拟定标准 |
| --- | --- |
| 数据有效性 | 来源、标签、划分、映射、测试隔离全部通过审计 |
| 迁移模块增益 | C 对 B，仅解释参数迁移贡献 |
| 先验模块增益 | D 对 C，仅解释先验贡献 |
| 产品候选 | 验证阶段在 A/B/C/D 内选定候选及最强可用对照，冻结后在测试集一次性比较；Log loss 改善至少 0.01，配对差值区间支持改善，并检查相对当前 A 的发布门槛 |
| 概率质量 | Brier 恶化的 95% 区间上界不超过 0.005 |
| 群体检查 | 已预先指定的技能/短历史群体，Log loss 恶化上界不超过 0.02；样本不足的范围继续回退 |
| 稳定性 | 多种子方向一致；无泄漏、非有限数值或无提示的覆盖丢失 |

数值为实施计划的初始建议，不是已有实验结论。P3 应根据目标域先导数据确定所需学生数、最小有意义增益、分组和多重比较处理，并冻结评估配置。测试规模不足以判定时继续影子运行。

例如 B=0.60、C=0.64、D=0.62 时，D 对 C 的改善不能授权部署 D。测试失败后保留已验收策略，新的选型必须重新开展预先冻结的评估，不反复从同一测试集挑赢家。

预测验收通过后，可进入受控推荐策略试点。教学验收以新题独立完成、跨题型迁移、预定间隔的延迟复习为主要结果；按学生分配策略、统一测题与帮助规则，并报告退出和缺失。现有固定三天复习入口作为实验规则记录。聊天满意度与开始率只作辅助指标。

## 9. P5：模型资源包与本地运行

保留 `StudentStateService` 作为入口，拟新增 `model_package.py` 与 `model_registry.py` 管理资源。先统一为当前加载器支持的 JSON 权重格式，消除默认 `.npz` 路径与导出名称的不一致。

公共资源包包含：`manifest.json`、`weights.json`、特征词表、技能映射、可选 `prototypes.json`、许可记录与去标识化验收摘要。清单记录包/模型版本、特征/标签/图谱版本、运行时兼容范围、课程覆盖、各文件哈希、发布签名和允许运行模式。

资源包冻结完整流程：事件 → 特征与缺失处理 → LSTM → 轨迹匹配 → 先验融合 → 概率校准 → 支持范围与回退。导出所有归一化参数、词表顺序、缺失/OOV规则、匹配温度、先验收缩、lambda 计算规则、校准器类型/参数及执行顺序、范围判据和 A 回退配置；任何影响输出的训练侧默认值均须进入带版本配置，缺失必要配置时拒绝加载。

包内自检使用非个人的固定测试事件，对比训练侧完整导出流程与安装包 NumPy 流程的 h/c、原始概率、融合概率、最终校准概率及回退状态。数值容差按字段冻结，覆盖缺失特征、OOV、零历史、先验关闭与不兼容版本；原有 LSTM 状态对齐是其中一层。

目录职责：

| 位置 | 内容 |
| --- | --- |
| 应用资源目录 `student-model/base/` | 随应用提供的只读公共模型 |
| 用户数据目录 `models/student-model/<version>/` | 用户导入的公共资源包、当前与上一可用版本指针 |
| 现有用户 SQLite 数据库 | 个人学习事件、预测、快照与档案配置，继续按 student_id 隔离 |

复用 Electron 当前路径解析链路与 `app.getPath('userData')`。个人状态继续留在现有数据库，无需为示意目录另迁一套存储。

资源解析顺序为：用户明确选定且兼容的版本 → 随包兼容版本 → EvidenceTracker。加载失败给出可诊断状态，原始判题与教学继续工作。

安装流程为：临时目录解包 → 路径与大小限制检查 → 哈希/签名/版本检查 → 数值和形状检查 → 推理自检 → 原子切换。签名必须验证到应用信任的发布密钥，单独校验包内自带哈希只证明一致性。实验包固定影子权限；产品策略开关由应用发布配置控制，资源包不能自行授权接管教学。

模型切换在版本边界生效，事件持续保存在事实库。后台按新参数重放到捕获的序号，再补齐增量并发布快照；期间采用证据策略，避免阻塞判题。失败保留上一个可用包。回滚同样检查版本绑定并重放。

所有模型重放任务复用 P2 的 `learning_generation`：读取历史时捕获代次，提交快照的同一事务内比较当前代次和模型版本，任一变化即丢弃结果。强制测试“旧任务读取 → 用户删除 → 旧任务提交”，确保不能写回旧信息；不另建第二套删除并发机制。

发布验收按实际目标平台执行：断网首启、无聊天 API Key、重启恢复、升级、回滚、损坏包、版本不兼容、删除后重启、长历史重放，以及真实安装路径。记录模型体积、安装增量、首载时间、推理 p50/p95、重放时间与峰值内存；性能预算在 P0 依据目标设备确定。
