## 记忆的版本与权限契约

编辑只更新 `object_json`、`predicate`、`confidence`，不能修改 owner、身份、来源或 `retrieval_enabled`。确认只允许 `MODEL_INFERRED → USER_CONFIRMED`，不等于重新授权检索；已经确认的记录重复确认幂等。检索开关由显式 toggle 更新。所有操作保留 owner 与 `deleted_at IS NULL` 条件；已删除或其他 owner 的记录返回 404，不返回冲突正文。

SQLite 与 InMemory 共享 `expected_updated_at` 比较交换语义。版本使用已有、按 owner 严格递增的微秒级 `updated_at`，不新增 schema revision。SQLite 的写入时钟使用聚合查询，避免为生成时间戳在 Python 中读取整组记录。

桌面 API 前缀为 `/api/v2/math-tutor/desktop`：

- `PUT /memory/{id}`：内容字段及 `expected_updated_at`。
- `POST /memory/{id}/confirm`：`{expected_updated_at}`。
- `PATCH /memory/{id}/retrieval`：`{enabled, expected_updated_at}`。
- 冲突返回 HTTP 409：`{code:"memory_conflict", detail:"这条记忆已在其他位置更新。", latest:<公开记忆投影>}`。最新投影包含准确版本与检索开关，不包含内部 owner 或其他用户记录。

新客户端始终原样传回服务端版本字符串，保留微秒精度。旧调用者可省略版本：服务仍使用请求内部读到的版本进行 CAS，并以窄字段更新保护检索权限；省略版本不能检测调用者在更早页面中拿到的旧内容。

编辑冲突后，最新状态更新到列表，当前草稿继续保留，保存暂停。用户可选择“保留草稿，按最新版本继续编辑”，或明确“放弃草稿，载入最新内容”。保存期间的新输入继续保持未保存状态，确认回执只推进服务端基线。确认与开关冲突需用户检查后重试，界面不会自动确认已变化的推测。

前端按完整微秒版本合并回执，同一毫秒内的旧响应也不能覆盖已经收到的新状态。保存期间输入框可以继续编辑；暂停取消、重开编辑及相互冲突的操作，避免旧回执重新显示已关闭的检索开关。数据层 CAS 与独立权限字段仍是最终保护。

## 文件工具的本轮意图

写意图由宿主生成，包含 owner、conversation、request、workspace、可识别相对目标路径及 create/update 模式。模型不能在工具参数中创建授权。读取正文、模型修复和插件回执仍属于不可信参考材料，不能扩大本轮意图。

已有 writable grant 是必要条件，明确的当前写命令也是必要条件。没有明确写动作时保留 read/list；“读一下刚才保存的 lesson.md”、文件名含“保存”、转述他人命令等不开放写定义。复合请求“读取 A 后把摘要保存为 B”仍可在当前有效授权与明确目标内执行。

执行阶段检查原始请求归属、目标路径与操作模式，并再次检查授权是否撤销。路径穿越、跨目录、错误目标或覆盖条件不符均拒绝；既有 `expected_hash` 内容校验继续保留。续写可以重绑当前可读目录，不能继承上轮保存意图。

授权使用宿主传入的完整原文，不再经教学提示词的“学生最新消息”抽取器处理，防止用户引用的对话包装剥掉外层禁止写入约束。动作序列遇到材料引入或冒号后的正文便停止扩展；未识别的目标保持只读，不把显式选择的只读或未知目录替换成另一个可写目录。

## 数学工具的统一预算

扩展是否绑定只决定工具集合。每次请求前估算本轮完整 history 与实际开放 schema，再按剩余额度下调输出上限；没有剩余额度时不调用 provider。返回后优先使用各方向真实 usage，包括真实的 0；缺失方向采用保守估算，原生 tool-call 参数也计入输出估算。

核验、绘图、扩展及续写遵守同一累计上限。超额后不再发下一次请求，停止原因保持 `TOKEN_LIMIT`，不声称回答完整。续写会传入当前请求的 `session_id` 与新 `request_id`，权限来自当前仍有效的宿主授权，不从模型文字或历史猜会话身份。

绘图补救无图返回时也保留预算终止原因，不能恢复为先前的 `COMPLETED/NATURAL_STOP`。集成回归用首答已耗 16380/16384 token 的 mock：补救 preflight 不再调用 provider，保留已有可靠正文，最终状态为 `PARTIAL/TOKEN_LIMIT`，诊断与终止回执一致。

## 有界候选与容量基准

模型记忆候选按 `updated_at DESC, created_at DESC, memory_id DESC` keyset 分页。默认页大小 **32**，总候选最多 **256**，最终仍最多 **20 条**、条目投影累计 **4800 字符**，单条最多 **1600 字符**；超大记录整条跳过，再补页。空数据、全部停用、尚待确认通过 count 聚合判断，无需为诊断物化全部正文。

诊断只保存候选总数、读取行数、页数、选中条数、选择耗时和 `selection_scan_limited`，不新增学生正文日志。超出 256 候选后存在尚未考虑的记录，明确标记触顶。管理页的完整记忆列表保持原接口；这里有界的是模型上下文候选。

复现命令：`PYTHONPATH=src python scripts/benchmark_memory_selection.py --rows 10000 --samples 15 --output docs/10月30号更新文档/assets/memory-benchmark.json`。基线使用原全量 `list_retrievable` 与完整记录选择规则，空结果也保留原 `list_nodes` 诊断读取；新路径使用实际 provider。合成数据放在临时 SQLite 数据库，输出仅为计数、时间与 Python 分配峰值。

| 合成场景 | 基线物化行数 | 新路径物化行数 | 选中结果 |
|---|---:|---:|---|
| 40 条普通记录 | 40 | 32 | 相同 |
| 1 万条，旧记录刚编辑 | 10000 | 32 | 相同，优先最新编辑 |
| 1 万条，最新 40 条超大 | 10000 | 64 | 相同，跳过超大条目补页 |
| 1 万条全部停用 / 全部待确认 | 10000 | 0 | 同为空，状态区分保留 |
| 1 万条，最新 300 条超大 | 10000 | 256 | 新路径达到上限，标记触顶，不冒充全量等价 |

基准含每场景 15 次采样、分配跟踪及预热，完整 p95/中位数/峰值见 [`memory-benchmark.json`](assets/memory-benchmark.json)。小集合增加聚合查询的固定开销；这些本机合成数值不用于承诺生产速度。没有新增匹配索引或 migration，因此仅保证 Python 实体读取与候选处理有界，不声称数据库内部扫描复杂度等于页大小。
