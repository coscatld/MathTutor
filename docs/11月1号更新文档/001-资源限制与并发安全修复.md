## 数学解析与计算预算

`ParseBudget` 在扩展题型、方程组和分数子解析之间共用；所有 token 分支通过同一个入口计数。递归前检查深度，数字转换前检查字面量长度。

| 默认上限 | 数值 |
|---|---:|
| 原始输入字符 | 4096 |
| 全部 token，含分数子式与方程组各式 | 256 |
| 活动解析嵌套层数 | 64 |
| 单个数字字面量的数字位数 | 512 |
| 精确有理数分子、分母及受控中间数 | 4096 bit |
| 指数绝对值 | 4096 |

常量幂在调用整数幂之前估算位数；有理数乘除先约去公因子，再检查乘积规模。加法、系数展开、仿射方程组及二次判别式使用同一精确运算边界。接受的结果仍为精确有理数，不改成浮点近似，也不关闭 Python 的整数转字符串限制。二次根排序改用精确分数，避免大系数转浮点溢出。

`MathComplexityError` 对外保留 `kind="unsupported"`，增加 `code="resource_limit"`；约束层拒绝后不进入模型回退，WebSocket 使用 `RESOURCE_LIMIT`。不会为超限题生成正确性凭证，下一条正常请求仍可处理。负指数仍属于原本不支持的题型，超大负指数先按预算拒绝。

这些是保守的成本边界：中间式过大时，即使最后可以抵消为小结果，也可能被拒绝。没有引入新的解析进程或线程，没有把“拒绝小于 100ms”写成已达成的性能承诺。

## 认证存储与执行

认证存储新增 `user/auth_initialized.json`。不存在账户文件且没有初始化标记时才进入首次设置；启用认证后，有效旧账户文件首次读取时补标记，账户文件和 owner ID 不重写。标记存在但账户文件丢失，或 JSON 截断、结构错误、深层损坏、ID/密码哈希无效、不可读，均要求恢复。

API 返回 HTTP 503、`code="auth_storage_recovery_required"`、`is_first_user=false`、`recovery_required=true`，不覆盖损坏账户文件。bootstrap 只用于明确尚未初始化的存储，不能覆盖损坏或初始化后丢失的账户。账户及 JWT secret 写入使用独立账户路径上的 OS 文件锁、唯一临时文件、POSIX 下 0600 权限、fsync 与原子替换；注册的检查、哈希和发布在同一写者事务内完成。

恢复时应保留并成组恢复账户文件、初始化标记和原签名 secret。旧版本如果在本轮标记存在前就已删除账户文件，仅凭缺失文件无法区分新安装与丢失历史；不能拿通用学习数据库推断曾经启用认证，因为该库也可能来自正常免登录使用。该迁移限制保留在本记录中。

默认新密码 bcrypt cost 仍为 12。接受的存储 cost 上限为 16；更高 cost 返回恢复错误，不执行计算，也不静默降低成本或重写哈希。序列化后的账户存储超过 256 KiB 时在发布标记及文件前拒绝，避免生成下一次无法读取的存储。

专属认证执行器最多提交 **2 个工作任务**，没有无界等待队列。容量满返回 503 `auth_busy`、`Retry-After: 1`；HTTP 请求取消不释放仍在运行的任务槽位，关闭时等待这些已拥有的任务结束。已接受的注册可能在客户端断连后提交，客户端通过状态或登录确认结果。

认证尝试预算为每进程每 60 秒 60 次、每 ASGI peer 12 次，最多保存 256 个 peer 桶；超额返回 429 `auth_rate_limited`、`Retry-After: 60`。不读取客户端直接提交的 Forwarded/X-Forwarded-For，内置启动器关闭自动代理头解释。外部代理部署需在 ASGI 服务端明确配置可信代理；此预算不是跨 worker 的共享限流。免登录桌面仍不开放注册。

## WebSocket 过载与停止

单个 reader 持有最多 16 条普通待处理消息，入队不等待容量。取消和呈现回执先分类；错误会话的停止请求不会取消其他工作。有效停止取消当前回合，并明确拒绝同一会话中尚未开始的请求；其他会话的排队请求保留。重复的同内容请求 ID 共用既有接收结果，不挤占队列；同 ID 不同内容继续按冲突处理。

尚未开始的拒绝回执关联原请求 ID，不进入请求执行日志，也不产生副作用；服务端允许沿用该 ID 重试。客户端停止自动重发明确拒绝的消息，仅结束相匹配的待处理请求并显示错误，不把另一个请求的拒绝当作当前回答完成。

新增的过载、停止和数学预算等 9 条固定系统提示跟随设置中的中文/英语选择。未知错误保留原文；学生输入和模型回答不经系统文案翻译，包含相同文字时也保持原样。

控制器到请求发布器之间的 `MathTutorEventStream` 也限制为 32 条事件，达到上限后生产端等待消费；关闭直接唤醒等待者，无需向已满队列再插入结束标记。这样 socket writer 上游也不会因快速输出而无限积压事件。

出站使用一个 writer、最多 32 条缓存，每次 socket send 最长 2 秒、关闭等待最长 1 秒。入站消息最多 65536 字符，出站单帧最多 262144 字符。出站缓存满或发送超时关闭过载连接并取消活动任务；过大入站帧按 1009 关闭，客户端停止自动重试该消息。传输层原始帧限制仍由 ASGI 服务承担，这些限制约束应用已收到的文本及应用缓存。

## 检索轮次语义

`RetrievalTurnStats` 由每次 `KnowledgeQA.respond` 创建，显式传给初检和本次 `KnowledgeTools`；finally 仅提交该 scope，重复关闭无效，已关闭 scope 不再被迟到工作修改。没有新增全局模型请求锁或隐式 ContextVar。

`rag_turn_semantics_version=2` 定义轮次为一次 response attempt：同一次调用内的模型/工具重试共用 scope；重新调用 respond 是新 attempt；持久化请求回放不会再次调用 respond。早退、异常和取消也关闭本次 attempt。其他直接使用检索器的入口仍记录调用级指标，不会被拼入某个知识问答轮次。

原有数值字段保留。`second_retrieval_rate` 为已关闭轮次中的二检轮数 / 初检轮数；一个轮次搜索三次也只算一个二检轮次。`average_second_search_calls` 保持进程工具调用次数 / 已关闭初检轮数的原有成本口径，单独看待。快照没有用户、会话、查询、原文或文档标题字段。

真实产品已有 owner 写锁，同一用户的请求本来会串行。双用户、双会话 WebSocket 回归使用固定身份替身与受控模型，其余检索、工具、SQLite 和请求日志走真实路径；分别覆盖两种结束顺序、取消一侧及回放。直接异步响应还覆盖不同 owner 的状态隔离。
