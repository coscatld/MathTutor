# 概念复查与学习闭环

日期：2026年11月11日（Asia/Shanghai）。本次按 research → experiment → checklist 完成四路调研、固定实验、实现与审查。新增功能入口是 **学习画像 → 概念复查**，支持中文和 English。

## 可以怎样使用

选择“分数加法”或“有符号数的减法”，先回答最多三道自由作答题。系统挑选能区分当前候选运算规则的题目，显示暂定的作答模式；遇到不一致的回答时保留不确定，后续反证可撤回观察。

诊断结束后进入新的独立练习。首次独立答对后，等待24小时，再做新的复习题与改变未知量位置的等式题。第一轮完成后等待72小时，第二轮复习和结构变化题完成后结束该回合。这是保守工程规则，尚未验证为最优间隔。

- 看解法之前先保存暴露记录；参考后答对属于受助练习，下一道新题再检查独立作答。
- 无法识别的数值输入保留原题，不计作答错；支持有界整数、小数和分数。
- 错过复习时间不会自动判错或生成遗忘结论；到期后仍可继续。
- 刷新、重启和重复请求不会清空已见题目或重复增加证据。
- 每条反馈附带刚才作答的题面，与下一题分开呈现。
- 独立练习、延迟复习、结构变化分别计数，不写入掌握度或DKT分数。
- 学习记录按用户隔离，隐私导出含摘要，清除学习历史会删除相应回合。

诊断中的连续追问只确认提交，不提前展示正确答案或纠错方法；主动求助会结束该轮独立诊断，再进入练习。题库用完后保留已有记录，不循环把旧题当首次作答。

## 调研如何影响实现

|---|---|---|

## 预注册与实验

Tier 1 改变的是任务构建和证据状态：从单题错误观察，扩展到竞争规则、主动追问、反证与跨日检查。组成方法已有研究先例，不称为新认知理论。Tier 2 的固定间隔与结构变化题在首轮实验之后接入。

[预注册](../research/learning-loop-20261111/PREREGISTRATION.md)固定seed=0、每回合最多三题、同一题库与准入条件。分数加法用于开发烟测，有符号减法整域留出用于主要评价。两域各200个已知规则病例、200个压力病例，共800个合成回合，分别运行主动、随机和固定顺序策略。200例是四条规则与可用题目变化的组合，不是200名学生。对照是明确命名的代理策略，原产品没有同样的候选规则输出，未伪造产品基线。

93道有限题目均经产品Parser → Solver → Verifier，并与独立精确有理数答案比对。评估模拟器用另一套初等公式计算作答，不调用待评估预测函数；机制仍由作者预先定义，不能替代真实认知真值。

| 留出域：有符号减法 | 主动选题 | 随机选题 | 固定顺序 |
|---|---:|---:|---:|
| 三题内正确支持模式 | 200/200 | 165/200 | 43/200 |
| 已支持但错误的已知规则 | 0/200 | 0/200 | 0/200 |
| 正确支持所需题数均值 | 2.000 | 2.224 | 2.884 |

主要看随机对照：覆盖率提高17.5个百分点，通过预设10个百分点的覆盖分支。题数减少约10.1%，**未达到15%的效率分支**。固定顺序容易连续抽到碰撞题，因此其较大差距不作为主要卖点。分数开发域主动与固定都为200/200、随机199/200，不表示所有数学内容均获益。

Apple M4、24GiB、本地CPU：最新记录的主动选题p95约0.101ms，共1,400次有效选择；全评估约0.160秒。此前混合策略的耗时统计已拆开修正，同一冻结数据复跑后的作答计数一致。此为小规模本地微基准，不是线上延迟承诺。没有模型训练、GPU作业、私有学生数据或付费模型调用。[机器可读结果](../research/learning-loop-20261111/metrics.json)

## 实验发现的限制与实际纠偏

单次失误、明显库外规则各50例，主动策略均保持未支持状态。但策略切换50例中仍有30例匹配一个暂定模式；刻意给出相同输出的未知机制50/50无法区分。因此不接入自动“稳定误概念确诊”，只展示可修正的作答模式与下一步练习。

复习时间在离线测试中使用注入时钟，只验证时间逻辑；结构变化题是缺项等式，不等于已证明广泛迁移。当前没有真人延迟测验，不能将本轮模拟覆盖、回合完成或历史WS检查称为学习收益。

checklist产生并完成了两项具体修正：分策略记录选题耗时；在解释旧记录前先核对题库策略，避免已删除题ID导致读取、导出失败。另补了反馈题面绑定、连续诊断不提前教学，以及帮助后重新用新题独立检查。[实验记录](../research/learning-loop-20261111/EXPERIMENT.md)、[独立审查](../research/learning-loop-20261111/AUDIT.md)

## 工程与验证

新增学习回合表由025增量迁移创建，保留历史023/024异常双头恢复和迁移前备份。JSON状态使用事务与比较交换；当前题、服务端时间、帮助标记与有界请求收据决定是否准入证据。旧策略记录保留且暂停继续，不被当前规则重新判定。

已完成核心数学测试34项、相关后端检查119项、Web检查334项和生产构建；浏览器覆盖中英文切换保留草稿、丢失响应后同请求重试、帮助/独立区分、到期复习、结构变化、刷新恢复、三种视口和明暗主题。浏览器使用合成API夹具；SQLite/API测试与安装包验收分别验证真实服务链路。最终本地 `scripts/check.py` 全量通过：3,937 项 Python、334 项 Web、57 项桌面契约检查；22 项 Python 和2项桌面检查因可选能力/产物范围跳过。三平台CI与安装包记录另行随构建保存。

## 复现

在已安装项目依赖的Python环境，从仓库根目录执行：

```sh
python scripts/learning_loop/train.py --data-dir scripts/learning_loop/fixtures --checkpoint-dir scripts/learning_loop/checkpoints --output-dir .runtime/learning-loop/train --seed 0
python scripts/learning_loop/eval.py --data-dir scripts/learning_loop/fixtures --checkpoint-dir scripts/learning_loop/checkpoints --output-dir .runtime/learning-loop/eval --seed 0
PYTHONPATH=src python -m pytest tests/test_diagnostic_probes.py tests/test_learning_loop.py
```

`train.py`是非训练的编译与冻结步骤，输出明确标注training=false；`eval.py`校验源码和夹具哈希。固定数据与清单在[scripts/learning_loop](../../scripts/learning_loop)。浏览器脚本为[smoke-learning-loop.mjs](../../web/scripts/smoke-learning-loop.mjs)，对生产构建的隔离前端运行，可用环境变量指定Playwright、Chrome与测试端口。
