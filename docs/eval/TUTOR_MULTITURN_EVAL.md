# 固定多轮辅导评测

这套评测用 15 个固定的多轮场景，经学生 WebSocket 驱动真实产品流程，每轮回复自动打分。**评分全部由规则和本地验证器完成，没有人工评分**，它是回归与发布门，不是人工质量评审；真实模型讲题质量的人工评审仍待完成。

## 怎么跑

```bash
# 模板教学（不接模型），CI 中随测试一起运行
PYTHONPATH=src python scripts/tutor_multiturn_eval.py --output build/eval

# 接真实模型：上线某个模型前必须跑，门不通过退出码为 1
PYTHONPATH=src MT_EVAL_API_KEY=... python scripts/tutor_multiturn_eval.py --mode live \
  --base-url https://api.deepseek.com/v1 --model deepseek-chat --output build/eval
```

场景定义在 `src/mathtutor/evaluation/tutor_multiturn_v1.json`，评分逻辑在 `src/mathtutor/evaluation/tutor_multiturn.py`。

## 六个维度（来自 tutor-v2 矩阵）

| 维度 | 自动检查 | 是否关键 |
|---|---|---|
| 数学正确 | 每轮回复里的算式都经 `verify_math` 核对，不能有未通过的算式 | 关键 |
| 目标相关 | 学生要提示 / 讲解 / 示例 / 图像时，出现对应的教学动作；指定内容出现在回复中 | |
| 学生证据 | 结束时独立 / 受助 / 看答案后的证据计数、画像中的错误概念与预期一致 | 证据计数为关键 |
| 可执行性 | 提示、讲解、示例类回复以提问或明确的下一步结尾 | |
| 适配 | 题目未完成或学生说不要答案时不出现答案；连续卡住后教学策略改变 | 提前给答案为关键 |
| 连贯 | 只出现预期的错误码、状态符合预期、没有未完成的输出、重发同一请求回放一致 | 意外错误为关键 |

发布门：关键检查全部通过，且各维度得分不低于门槛（数学正确 1.0、学生证据 1.0、连贯 0.95、目标相关 0.9、适配 0.9、可执行性 0.8）。

## 能证明什么，不能证明什么

- 能证明：教学流程的答案边界、证据分流、算式核验和状态机在这些场景下没有走样；接入的模型如果写出错误算式，门会失败（`tests/test_tutor_multiturn_eval.py` 用一个故意算错的模型验证了这一点）；回复中提前出现答案时，「适配」维度的关键检查会失败。
- 不能证明：讲解是否清楚、是否真的帮助学生学会、长期效果。这些需要人工评审和学习效果实验，目前都没有做。
- 文字说明不在核验范围内，只有算式会被核对。
