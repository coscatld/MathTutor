# 固定多轮辅导评测

这套评测用 16 个固定的多轮场景，经学生 WebSocket 驱动真实产品流程，每轮回复自动打分。**评分全部由规则和本地验证器完成，没有人工评分**，它是回归与发布门，不是人工质量评审；真实模型讲题质量的人工评审仍待完成。

## 怎么跑

```bash
# 模板教学（不接模型），CI 中随测试一起运行
PYTHONPATH=src python scripts/tutor_multiturn_eval.py --output build/eval

# 接真实模型：上线某个模型前必须跑，门不通过退出码为 1
PYTHONPATH=src MT_EVAL_API_KEY=... python scripts/tutor_multiturn_eval.py --mode live \
  --base-url https://api.deepseek.com/v1 --model deepseek-chat --output build/eval
```

场景定义在 `src/mathtutor/evaluation/tutor_multiturn_v1.json`，评分逻辑在 `src/mathtutor/evaluation/tutor_multiturn.py`。

可以用 `--only linear-independent` 运行指定子集。未知ID（包括已知与未知混合）或空的`--only`会以退出码2报错，不创建结果文件；零场景或没有执行检查的结果不会通过。合法子集检查通过时退出0，报告显示“子集回归通过”，并列出实际覆盖数与未运行ID。JSON的`gate.passed`表示已运行检查的结果；发布脚本应读取`release_gate.passed`，它仅在完整套件通过时为true。旧的JSON报告没有该字段，需要重新运行，不能默认当作全套通过。

报告文件、标准输出和错误诊断均使用UTF-8，重定向输出的Windows环境也可读取中文；消费CLI输出的脚本应按UTF-8解码。

## 六个维度（来自 tutor-v2 矩阵）

| 维度 | 自动检查 | 是否关键 |
|---|---|---|
| 已核验算式正确 | 保留 `verify_math` 的 verified / refuted / unchecked，已检查项正确率为 verified / (verified + refuted)，同时展示覆盖率 | 发现反例为关键失败 |
| 目标相关 | 学生要提示 / 讲解 / 示例 / 图像时，出现对应的教学动作；指定内容出现在回复中 | |
| 学生证据 | 结束时独立 / 受助 / 看答案后的证据计数、画像中的错误概念与预期一致 | 证据计数为关键 |
| 可执行性 | 提示、讲解、示例类回复以提问或明确的下一步结尾 | |
| 适配 | 题目未完成或学生说不要答案时不出现答案；连续卡住后教学策略改变 | 提前给答案为关键 |
| 连贯 | 只出现预期的错误码、状态符合预期、没有未完成的输出、重发同一请求回放一致 | 意外错误为关键 |

发布门：关键检查全部通过，且有适用检查的各维度得分不低于门槛（已核验算式正确 1.0、学生证据 1.0、连贯 0.95、目标相关 0.9、适配 0.9、可执行性 0.8）。完整场景覆盖仍由 `release_gate` 单独约束。

## 数学口径 v2

报告的 `metric_version` 为 `tutor-multiturn-metrics-v2`，与场景集合版本分别记录。每轮的 `math` 和场景的 `math_assessments` 保留核验计数及状态：

| 状态 | 含义与计分 |
|---|---|
| `verified` | 至少一项已核验，未检出反例，也没有提取后未覆盖的项 |
| `partial` | 同时存在已核验与未覆盖项；只有已检查项进入正确率 |
| `refuted` | 至少发现一个支持形式的反例，关键检查失败 |
| `unchecked` | 提取出的项全部未覆盖，正确率为 N/A，需人工复核 |
| `not_applicable` | 没有提取出数学声明，如合法纯文字追问；不进入数学正确分母 |
| `not_delivered` | 没有合格的完成交付，不能获得数学通过计数 |

`math.coverage` 为 `(verified + refuted) / (verified + refuted + unchecked)`；无提取项时为 `null`。计数单位是核验器的检查项，一条链式等式可能产生多项检查。这一覆盖率只针对核验器提取到的内容，不代表全文、图形、文字证明或未识别公式的覆盖率。

所有非空正文都保留核验诊断；只有完整交付的检查项进入正确率和覆盖率。其他交付的计数汇总在 `math.delivery_excluded`，其中发现的反例仍是关键失败。全未覆盖的可选轮次不被机械判错，但也不获得数学通过计数。

需要推导或答案的轮次在场景 `expect` 中显式设置 `require_verified_math: true`：必须完成交付、至少有一项已核验内容且没有反例。空泛追问不能满足该要求。普通启发式追问保持可选；纯文字合法子集仍可通过其他适用检查，数学得分保持 `null`，不会凭 N/A 得到数学正确票数。

`math.legacy_v1` 在同一次运行中并列计算旧口径“合格非空轮次未发现反例”的通过数、分母与得分，供迁移核对。新版按检查项、旧版按轮次计数，分母不同，不能直接比较为教学效果提升。历史报告不回写新版分数。

## 能证明什么，不能证明什么

- 能证明：教学流程的答案边界、证据分流、算式核验和状态机在这些场景下没有走样；接入的模型如果写出错误算式，门会失败（`tests/test_tutor_multiturn_eval.py` 用一个故意算错的模型验证了这一点）；回复中提前出现答案时，「适配」维度的关键检查会失败。
- 不能证明：讲解是否清楚、是否真的帮助学生学会、长期效果。这些需要人工评审和学习效果实验，目前都没有做。
- 文字说明不在核验范围内；未支持或未提取的公式也不能据此声称已核验。
