# 本地服务安全与资源边界

日期：2026-10-25（Asia/Shanghai）。基线：`ab7adf3`。

本轮落实每日建议中的五项问题。以下记录源码行为、开发配置和实际验证范围。

## 改动

| 建议 | 实现 |
| --- | --- |
| MT-SEC-001 | HTTP 和 WebSocket 共用 ASGI 来源门，在读取业务请求体及取得 owner 前检查精确 Host、Origin；无 Origin 的原生请求须携带 bridge 凭证；HTTP 变更须有 bridge 或自定义 CSRF 请求头。Electron 每次启动生成随机凭证，通过子进程环境、受信窗口请求和本地代理传递。代理先核验来源，再向后端添加凭证。 |
| MT-UPLOAD-001 | 所有文件上传统一有界读取 `limit + 1`，超限返回 413，关闭操作在取消作用域中受到保护。ASGI 对实际收到的字节累计计数，覆盖缺少或伪造 Content-Length 的请求，并在超限时停止交给 multipart 解析器。 |
| MT-PARSE-001 | 默认解析与分块使用 2 个线程、最多 4 个运行或排队任务；队列满立即拒绝。增加页数、文本、内容块、图片数量和资产总量预算，使用阶段资产目录并跟踪取消与关闭；chunks、FTS、向量失效和文档元数据在一次事务中发布。 |
| MT-RUNTIME-001 | 生产 LoggingDispatchSink 只保留投递计数和白名单日志，不持有事件历史。需要完整断言的测试显式注入 RecordingSink。 |
| MT-BACKUP-001 | 备份目录准备、stat、hash、manifest 发布和手动/定时 retention 均进入受管理 worker；恢复和关闭前继续排空这些 worker。 |

上传保留独立配额：普通资料 20 MiB、图片 10 MiB、社区分享单文件 32 MiB；社区多文件资料仍共用 20 MiB 文件内容总量，并单独留出 multipart 元数据空间。Next 的代理缓存从 210 MiB 缩至 34 MiB。该 Next 配置只限制缓存，硬性拒绝由后端 ASGI 字节计数及业务文件限制执行。

`starlette>=1.6` 成为显式依赖，以确保 multipart 在接收失败或取消时关闭已创建的临时文件。旧版 parser 仅捕获 MultiPartException，不能提供本轮所需的异常清理保证。上传 helper 另用取消屏蔽保护磁盘 spool 的异步关闭。

默认解析预算：500 页、200 万提取字符、2 万内容块、256 个图片资产、32 MiB 资产内容，单个解析或分块任务使用 30 秒协作 deadline。线程可让事件循环继续调度，但无法强制打断第三方 PDF 库的一次长调用，也不能硬限制其瞬时 RSS；取消和关闭会等待已准入任务释放文件。可选 PyMuPDF 分支使用全局锁串行调用。MinerU 超时会 kill/join 直接 CLI 进程，未提供衍生进程树和运行中临时磁盘的 OS 级隔离。需要强制时间和内存隔离时，应另做跨平台进程 worker 与打包验收。

## 本地开发与原生客户端

桌面启动器自动设置随机端口、精确来源和本次运行的凭证。浏览器开发入口需显式设置：

```text
MATHTUTOR_ENVIRONMENT=development
MATHTUTOR_BROWSER_DEV=1
MATHTUTOR_ALLOWED_ORIGINS=http://127.0.0.1:3000
MATHTUTOR_ALLOWED_HOSTS=127.0.0.1:8001
MATHTUTOR_API_BASE_URL=http://127.0.0.1:8001
```

将 Origin 和 Host 改成实际使用的 scheme、hostname、port；`localhost` 与 `127.0.0.1`、不同端口分别配置。生产环境忽略免登录浏览器开发开关。账号部署同样需要配置实际网站 Origin 和后端 Host。

前端 `apiFetch` 自动带 `X-MathTutor-CSRF: 1`。开发代理将具有精确 Host、浏览器同源 Fetch Metadata 和该自定义头的无 Origin 浏览器读取识别为受信请求，再补上已配置的 Origin；同源图片读取和用户点击的下载另按浏览器控制的 destination/mode/user 元数据识别。外站来源和简单表单请求不会取得这一待遇。

原生 HTTP/WS 客户端使用 `X-MathTutor-Bridge`，值来自服务端配置的 `MATHTUTOR_BRIDGE_SECRET`。凭证只在运行环境中设置，避免写入源码、静态 JS、URL 和日志。测试专用凭证只由 pytest fixture 提供，不增加产品模式下的测试主机例外。

离线评测、回放和 RAG 验收工具为自己的进程内临时应用生成独立凭证，并显式传给 TestClient；它们无需放宽真实应用的来源规则。

本轮使用临时测试资料与数据库。跨浏览器本地网络权限行为、真实学生工作负载、代表性慢盘的大数据库延迟分位数、长期稳定阶段 RSS，以及 Windows/Linux 新安装包仍需在相应环境验收。本轮工程修复不代表已经测得教学效果变化。
