## 去重、标签与映射

以 `(user_id, order_id)` 标识原始 problem log；同记录多技能行合并技能集合，其他关键字段冲突则报错。同一学生重做同题占用首次位置；不同学生做同题保留。`order_id` 只作为官方定义的相对时序，不伪造时间戳或题间间隔。

[官方字段字典](https://sites.google.com/site/assistmentsdata/an-explanation-on-how-to-interpret-our-data-sets)明确 `first_action` 的 0/1/2 分别是作答、提示、分步辅导。主问题首次动作是作答且评分可核验时，保留首次结果；先错后使用提示仍为 0。首次求助、未知、重复题、脚手架、开放回答及矛盾字段不进入主标签。完整动作序列缺失，不能由聚合次数重建后续帮助顺序。

源技能共有 123 个 ID。`assist2009-mt-topic-v1` 显式映射 10 个源技能 ID 到产品 6/13 个主题：有理数与符号运算、分数运算、分配律、一次方程隔离未知数、二次方程求根、方程组完整解。其余保持未映射，多技能题只有全部源标签均能映射才进入映射子集。具体 ID、名称和映射表保存在 JSON 及适配器中。

这些是主题层面的代理对应。例如方程组题不会被同时标为“消元法”和“代入法”；源数据缺题干与解法证据，6/13 不能解释为产品全部细粒度能力已经得到训练验证。

## 留出与精确检查点

固定种子 17、29、43，按学生 60%/20%/20% 划分；主协议允许不同学生共享课程题。压力协议同时留出学生与题目，或学生与 `template_id` 题族；仅保留两种分组落在同一折的记录，明确报告丢弃规模。模板 ID 是来源定义的相似题族代理，不声称覆盖全部文本近重复。

检查点 k=0/1/3/5/10 表示此前经过 k 条主问题记录，包括求助、未知和重做；历史包含其间脚手架。取紧随其后的主问题，不跳到后续可评分题凑数。查询仅含题目身份与技能，标签独立返回，不含该题正确性、帮助次数或耗时。双冷启动的 k 只按留出后保留的历史计数。
