# 社区资源下一阶段计划

本页是 0.7.0 发布后的开发计划，不代表下列功能已经上线。先完成当前版本发布，再按资源索引、版本管理、贡献审核的顺序推进；每阶段必须给出可复现的测试证据。

## 当前可以使用的能力

用户在“社区 → 发现资源”导入个人资料和题库，在“我的插件”单独导入、启停、配置和导出插件。题库作为可编辑的个人副本保存，不自动挂载到当前对话，也不改写官方练习库。

开发接口已有目录订阅与显式刷新、资源哈希校验和按用户保存的导入记录。插件已有版本递增检查、同版本内容不可替换、配置保留与升级停用。当前普通界面没有 GitHub 精选资源索引、历史版本回滚或在线贡献审核平台。

Python / TypeScript 代码插件需要用户逐项同意 `execute_local_code` 后启用，升级会清除此代码同意并停用。代码按本机账户权限运行，**不是操作系统沙盒**。声明式教学插件只运行宿主既有工作流；教学说明、题目答案和插件结果均为参考内容，宿主不会据此自动授予权限或写入掌握度、作答及 DKT 学习事件。这不代表任意本机代码已被限制为无法访问文件或网络。

## 1. GitHub 资源索引

目标是让用户查找带真实来源的公开题库和插件，阅读详情后主动下载或导入。优先建立可审查的仓库目录，不上传学生数据，不虚构下载量、评分或推荐理由。

计划提供资源名称、稳定 ID、版本、作者、许可证、适用年级、说明、更新记录、源码地址、反馈入口、下载地址和包哈希。目录不携带用户凭据；外链不能包含令牌。详情明确区分项目示例、作者声明与维护者审核记录。

验收条件：

- 公开、可复现的示例目录通过真实解析器；缺少许可、版本或包哈希时拒绝发布，不能把“字段已填写”视为版权核验完成。
- 搜索、年级和类型筛选返回真实目录项；没有资源时显示空结果。
- 用户显式刷新仅获取有界元数据，不执行源码、不预装依赖、不下载资源包；下载和导入由后续明确动作触发。
- 复用现有 HTTPS、DNS 固定地址、无重定向和包哈希限制；本地、私网、跨源包地址、篡改包和超限目录的回归测试通过。
- 刷新失败保留旧缓存并标明过期与失败原因，不伪报成功；删除订阅不删除已导入个人库或其他用户的数据。
- UI 和 API 均验证用户隔离；常规浏览不携带对话、学习记录、API Key 或本地文件路径。

## 2. 插件版本管理

目标是清楚展示当前安装版本、已知可用版本和变更，允许用户作出升级决定。目录发现更新不等于执行升级；现有同 ID、同版本的内容不可悄悄改变。

计划补充按用户保存的安装历史、版本详情与更新状态，以及经过设计和测试的回退流程。现有升级检查与导入记录可以复用；它们不等同于已经实现可恢复的历史代码包存储。

验收条件：

- 相同包重复导入保持幂等；相同版本不同内容拒绝，旧版本和不同工作流不能冒充普通升级。
- 升级前展示作者变更、文件或哈希变化、更新说明与权限差异；不静默替换用户配置或已编辑题库。
- 代码插件升级后停用并清除 `execute_local_code` 同意，重新明确同意后才允许 `/命令` 或页面运行；目录签名、审核标记、曾经启用或旧版本同意均不能代替这次授权。
- 声明式插件升级继续停用，新增数据权限不得自动授予；运行中授权或版本改变时阻止旧结果按新权限交付。
- 回退如实现，必须保留可校验的目标包，采用独立显式动作并重新确认信任；不能简单取消当前的降级拒绝规则。
- 断网、升级中断、磁盘写入失败、重复请求、卸载、跨用户和恢复数据库后的授权状态都有实际回归；不能宣称多个独立存储具有尚未实现的原子事务。

## 3. 社区贡献审核

目标是以 GitHub Issue / Pull Request 为可追溯入口，审核资源的来源、格式、数学内容和执行边界。维护者审核不是 OS 沙盒、恶意代码检测保证或数学形式化证明。

计划为题库、声明式插件和代码插件分别提供投稿清单与审核记录。发布索引应指向不可变版本和明确的提交或发布附件；通过审核的版本更新仍需要重新评审变更。

验收条件：

- 投稿必须说明真实作者或署名、许可、来源、版本、兼容范围、使用方式、预期结果及限制；包含隐私、凭据或无权分享内容的投稿不进入发布目录。
- 题库通过生产导入器，逐题抽查或按约定范围审核答案、条件、单位和讲解，并记录审核覆盖范围；参考答案不升级为学生掌握证据。
- 声明式插件通过现有清单校验与真实工作流运行；代码包经过人工源码审查，再在明确授权的测试环境验证超时、输出、错误和运行结果，不在审阅或安装时执行代码。
- CI 使用模拟数据和零付费调用，至少覆盖 Windows / macOS 的 UTF-8、换行、包内精确字节、路径、哈希与默认停用行为；PR 检查不向第三方代码暴露仓库密钥或发行凭据。
- 审核决定记录版本、包哈希、关联 PR、检查项目和已知限制；撤回有问题的目录项不擅自删除用户资料，也不假定远端撤回能自动终止已获本机授权的代码。
- 保留安全问题的私密披露渠道。拒绝或撤回资源的原因可追溯，不能将“已审核”作为自动启用、免除本地代码同意或绕过答案披露的依据。

## 证据与交付边界

每阶段通过针对性回归后再合入，并更新功能文档。安装包依其构建提交和哈希追溯；仓库新增指南、示例或索引不会自动改变已经发布的 0.7.0 安装包。已公开的基准成绩继续对应原实验，不能用资源数量或示例测试通过率推断模型教学质量提高。
